DB 쿼리 감사 로그 시스템

Apache Superset + PostgreSQL 전용 사용법 · Azure Cloud / RedHat 9.7
Python 표준 라이브러리 전용 외부 패키지 없음 비암호화 연결(sslmode=disable) 전용

1 시스템 개요

Apache Superset이 PostgreSQL에 실행하는 모든 쿼리를 6하원칙(누가·언제·어디서·무엇을·어떻게·왜)에 따라 자동으로 로그 파일에 기록한다. Superset 소스코드와 PostgreSQL 서버 설정을 변경하지 않고 적용할 수 있다.

항목내용
감사 대상Superset → PostgreSQL 모든 SQL (SELECT / DML / DDL)
대상 DB 서버Azure Cloud / RedHat 9.7 / PostgreSQL
암호화 전제Superset ↔ PostgreSQL 간 비암호화 연결 (sslmode=disable)
외부 패키지없음 — Python 표준 라이브러리만 사용
로그 형식JSON Lines (.jsonl), 일별 파일 로테이션, SHA-256 무결성 해시
조회 방법웹 브라우저(포트 8888) 또는 CLI

감사 방식 비교

★ 방식 A — 권장

pg_proxy.py (TCP 프록시)

  • Superset과 PG 사이 TCP 프록시 삽입
  • root 권한 불필요
  • PG 서버 설정 변경 없음
  • Superset DB URI 변경 필요
  • PG 서버 또는 별도 서버에서 실행
방식 B

pg_sniffer.py (패킷 스니퍼)

  • OS raw socket으로 패킷 감청
  • root 또는 CAP_NET_RAW 필요
  • Superset 설정 변경 없음
  • PG 서버에만 설치 가능
  • SELinux Enforcing 시 추가 설정 필요

4 폐쇄망 반입 절차

사전 확인 — 대상 서버에서 실행

# 1. OS 버전
cat /etc/os-release | grep -E "NAME|VERSION"

# 2. Python 설치 여부 (3.8 이상이면 추가 준비 불필요)
python3 --version

# 3. PostgreSQL 포트 확인
sudo ss -tlnp | grep 5432

# 4. PostgreSQL SSL 설정 확인 (반드시 off 여야 함)
sudo -u postgres psql -c "SHOW ssl;"

# 5. SELinux 상태 (Enforcing이면 방식 B raw socket 차단 가능)
getenforce

# 6. 방화벽 포트 확인 (8888 웹뷰어용)
sudo firewall-cmd --list-all
RedHat 9.7 은 Python 3.9 이상이 기본 설치되어 있으므로 대부분 python3만 확인하면 된다.

5 config.py 설정

이 파일을 가장 먼저 수정한다. 기본값은 localhost이므로 실제 서버 정보로 변경해야 한다. 
# ── PostgreSQL 연결 정보 ────────────────────────────────────────────
PG_HOST   = "10.0.0.5"        # ★ 실제 PostgreSQL 서버 IP
PG_PORT   = 5432               # PostgreSQL 리스너 포트 (기본 5432)
PG_DB     = "superset_db"     # ★ 실제 데이터베이스 이름
PG_SCHEMA = "public"          # 감사할 스키마 (보통 public)

# ── 로그 저장 경로 ──────────────────────────────────────────────────
LOG_DIR = Path("/opt/audit/logs")   # ★ 절대경로 권장

현재 스키마 확인 SQL

-- PostgreSQL에서 실행
SELECT schema_name FROM information_schema.schemata ORDER BY 1;
SELECT DISTINCT table_schema FROM information_schema.tables
  WHERE table_type = 'BASE TABLE' ORDER BY 1;

6 방식 A: pg_proxy.py (권장)

실행

python3 pg_proxy.py \
    --pg-host 127.0.0.1 \        # PostgreSQL 실제 주소
    --pg-port 5432 \              # PostgreSQL 실제 포트
    --listen-port 5433 \          # Superset이 접속할 포트
    --db-name superset_db \       # 로그에 기록할 DB명
    --db-schema public            # 로그에 기록할 스키마명
파라미터설명기본값
--listen-host프록시 바인딩 주소0.0.0.0
--listen-portSuperset이 접속할 포트5433
--pg-host실제 PostgreSQL 서버 IPconfig.py PG_HOST
--pg-port실제 PostgreSQL 포트5432
--db-name로그용 DB명config.py PG_DB
--db-schema로그용 스키마명config.py PG_SCHEMA

Superset DB URI 변경

방식 A 사용 시 이 단계가 필수다. URI를 변경해야 Superset의 쿼리가 프록시를 경유한다.

Superset 관리 화면: Settings → Database Connections → 대상 DB 선택 → Edit

SQLAlchemy URI
변경 전 postgresql+psycopg2://user:password@10.0.0.5:5432/superset_db
변경 후 postgresql+psycopg2://user:password@10.0.0.5:5433/superset_db?sslmode=disable
sslmode=disable 을 반드시 명시한다. 생략 시 Superset/SQLAlchemy가 SSL을 먼저 시도하고, 프록시가 SSL 세션을 감지하면 해당 연결의 SQL 추출을 중단한다.

systemd 서비스 등록 (자동 시작)

sudo tee /etc/systemd/system/pg-audit-proxy.service << 'EOF'
[Unit]
Description=PostgreSQL Audit Proxy for Superset
After=network.target postgresql.service

[Service]
ExecStart=/usr/bin/python3 /opt/audit/deploy_postgreSQL/pg_proxy.py \
    --pg-host 127.0.0.1 \
    --pg-port 5432 \
    --listen-port 5433 \
    --db-name superset_db \
    --db-schema public
WorkingDirectory=/opt/audit/deploy_postgreSQL
Restart=always
RestartSec=5
User=audituser

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now pg-audit-proxy
sudo systemctl status pg-audit-proxy

7 방식 B: pg_sniffer.py

실행

sudo python3 pg_sniffer.py \
    --pg-port 5432 \
    --db-server 10.0.0.5 \       # 로그용 PG 서버 표시명
    --db-name superset_db \
    --db-schema public

root 없이 실행 (CAP_NET_RAW)

# python3에 CAP_NET_RAW capability 부여 (1회 실행)
sudo setcap cap_net_raw+ep /usr/bin/python3

# 이후 일반 계정으로 실행 가능
python3 pg_sniffer.py --pg-port 5432 --db-name superset_db

SELinux Enforcing 환경 추가 설정

# SELinux 상태 확인
getenforce

# Permissive 모드로 임시 전환 (테스트용)
sudo setenforce 0

# 영구적으로 Permissive 로 변경 (/etc/selinux/config 수정)
sudo sed -i 's/SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config

systemd 서비스 등록

sudo tee /etc/systemd/system/pg-audit-sniffer.service << 'EOF'
[Unit]
Description=PostgreSQL Audit Sniffer for Superset
After=network.target

[Service]
ExecStart=/usr/bin/python3 /opt/audit/deploy_postgreSQL/pg_sniffer.py \
    --pg-port 5432 \
    --db-name superset_db \
    --db-schema public
WorkingDirectory=/opt/audit/deploy_postgreSQL
Restart=always
RestartSec=5
User=root

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now pg-audit-sniffer

방화벽 설정 — 조회 담당자 IP만 허용 (RedHat 9 / firewalld)

# 특정 IP 대역만 8888 허용 (예: 192.168.10.0/24)
sudo firewall-cmd --permanent --add-rich-rule='
  rule family="ipv4"
  source address="192.168.10.0/24"
  port protocol="tcp" port="8888"
  accept'
sudo firewall-cmd --reload

# 설정 확인
sudo firewall-cmd --list-rich-rules
전체 IP 허용 금지. 웹 뷰어는 인증 기능이 없으므로 방화벽에서 조회 담당자 IP만 반드시 제한한다.

10 운영 체크리스트

초기 설치

  • config.py 수정 완료 (PG_HOST, PG_PORT, PG_DB, PG_SCHEMA, LOG_DIR)
  • PostgreSQL SSL 확인 완료 (SHOW ssl; → off)
  • logs/ 디렉토리 쓰기 권한 확인 (chmod 700 logs/)
  • [방식 A] pg_proxy.py 실행 확인 → Superset DB URI 변경 → 연결 테스트 성공
  • [방식 B] pg_sniffer.py 실행 (root 또는 CAP_NET_RAW 확인)
  • Superset에서 쿼리 실행 → logs/*.jsonl 파일 생성 확인
  • 웹 뷰어 실행 → 사용자 PC 브라우저에서 http://서버IP:8888 접속 성공
  • 방화벽 8888 포트 → 조회 담당자 IP만 허용 확인

서비스 등록

  • systemd 서비스 등록 완료 (pg-audit-proxy 또는 pg-audit-sniffer)
  • systemd 서비스 등록 완료 (audit-log-viewer)
  • 서버 재부팅 후 자동 시작 확인 (systemctl status)

운영 중

  • 로그 파일 주기적 백업 및 보관 기간 정책 수립 (6개월 이상 권장)
  • 로그 무결성 정기 검증 (웹 뷰어 /verify 메뉴 또는 python3 log_viewer.py --verify)
  • 로그 파티션 용량 모니터링 (200 MB/파일 자동 분할)
  • 방화벽 8888 포트 IP 제한 정기 점검
