# Oracle TNS 쿼리 감사 로그 시스템 — 사용법

## 시스템 개요

Oracle DB로 전달되는 SQL 쿼리를 **OS 원시 소켓(Raw Socket)** 으로 수동 감청해 **6하원칙(누가/언제/어디서/무엇을/어떻게/왜)** 에 따라 자동으로 로그를 기록한다. 애플리케이션과 Oracle 서버 설정을 전혀 변경하지 않아도 된다.

- Python 표준 라이브러리만 사용 (외부 패키지 없음)
- 폐쇄망 반입 가능 (PyInstaller로 단일 실행파일 빌드 지원)
- 일별 JSONL 로그 + SHA-256 무결성 해시
- 웹(포트 8888) / CLI 조회 모두 지원

### 아키텍처

```
[Oracle 클라이언트 앱] ──TCP:1521──▶ [Oracle 서버]
                                           │
                             OS 네트워크 스택이 패킷 복사
                                           │
                               [packet_sniffer.py]
                               TNS 패킷 분석 → SQL 추출
                                           │
                              logs/audit_query_YYYYMMDD.jsonl
                                           │
                        ┌──────────────────┤
                        ▼                  ▼
               log_viewer_web.py     log_viewer.py
               (http://호스트:8888)   (CLI)
```

## 배포 패키지 구성

`deploy/` 폴더에 폐쇄망 반입에 필요한 파일만 담았다.

```
deploy/
├── config.py              # DB·로그 경로 등 설정 (가장 먼저 수정)
├── query_logger.py        # 로그 기록·읽기·검증 핵심 엔진
├── oracle_proxy.py        # TNS 프로토콜 파서 (packet_sniffer가 내부적으로 사용)
├── packet_sniffer.py      # 메인 감사 수집 프로그램
├── log_viewer_web.py      # 웹 조회 서버
├── log_viewer.py          # CLI 조회
└── logs/                  # 감사 로그 저장 폴더 (자동 생성됨)
```

> `oracle_proxy.py`는 TCP 프록시로 직접 실행하지 않는다. `packet_sniffer.py`가 TNS 프로토콜 파서로 내부에서 import한다.

## 설정 파일 (config.py) — 가장 먼저 수정

```python
LOG_DIR    = "logs"           # 로그 저장 경로 (별도 파티션 권장: "/var/log/audit")
DB_SERVER  = "192.168.1.10"   # Oracle 서버 IP 또는 호스트명 (로그 기록용 표시값)
DB_NAME    = "ORCL"           # Oracle 서비스명 / SID
DB_SCHEMA  = "FINDB"          # 스키마(소유자) 이름
```

## 설치 절차

### Python이 설치된 환경

```bash
# 1. 파일 복사
mkdir -p /opt/audit/logs
cp deploy/* /opt/audit/

# 2. config.py 수정
vi /opt/audit/config.py

# 3. 동작 테스트 (Linux: root 필수)
sudo python3 /opt/audit/packet_sniffer.py --oracle-port 1521

# 4. 로그 확인 (쿼리 실행 후)
ls /opt/audit/logs/
```

Windows(관리자 CMD):

```cmd
md C:\audit\logs
copy deploy\* C:\audit\
python C:\audit\packet_sniffer.py --oracle-port 1521 --bind-ip 0.0.0.0
```

### 폐쇄망 — Python이 없는 Oracle 서버 대응

Oracle 서버에 Python을 설치할 수 없을 때 아래 방법 중 선택한다.

---

**방법 1 (권장) — PyInstaller 단일 실행파일**

동일 OS·아키텍처의 외부망 PC에서 빌드 후 실행파일 하나만 반입한다.

```bash
# 외부망 빌드 PC (같은 OS, 같은 CPU 아키텍처 필수)
pip install pyinstaller
cd deploy/

# config.py를 실제 운영값으로 수정한 뒤 빌드
pyinstaller --onefile packet_sniffer.py
# → dist/packet_sniffer (Linux) 또는 dist/packet_sniffer.exe (Windows)
```

빌드 파일 하나만 Oracle 서버로 복사해 실행:

```bash
chmod +x dist/packet_sniffer
sudo ./dist/packet_sniffer --oracle-port 1521
```

> `config.py`는 빌드 시 실행파일 안에 포함된다. **빌드 전에 반드시 실제 운영값으로 수정**한다.

---

**방법 2 — SPAN 포트 / 네트워크 TAP 활용**

Oracle 서버에 아무것도 설치하지 않는다. 스위치 SPAN 포트나 TAP 장비로 Oracle 트래픽을 미러링하고, Python이 있는 별도 감사 서버에서 실행한다.

```
[앱 서버] ──▶ [Oracle 서버]
                    │
              (스위치 SPAN/TAP)
                    │
              [감사 서버: packet_sniffer.py]
```

---

**방법 3 — Python 오프라인 설치**

Python 설치 파일을 USB 또는 내부 전송으로 반입해 Oracle 서버에 설치한 뒤 deploy 파일을 복사한다.

| 상황 | 권장 방법 |
|------|-----------|
| Oracle 서버와 동일 OS 빌드 환경 있음 | 방법 1 (PyInstaller) |
| Oracle 서버에 아무것도 설치 불가 | 방법 2 (SPAN/TAP) |
| 내부 반입 절차로 설치 가능 | 방법 3 (Python 오프라인) |

## 구동 옵션

```bash
# Linux (root 필수)
sudo python3 packet_sniffer.py \
    --oracle-port 1521 \     # 감청할 Oracle TNS 리스너 포트 (기본 1521)

python packet_sniffer.py \
    --oracle-port 1521 \
    --bind-ip 0.0.0.0 \      # 바인딩 인터페이스 IP (Windows 전용)
    --db-name ORCL
```

## 서비스 등록 (재부팅 후 자동 시작)

**Linux — systemd**

```bash
cat > /etc/systemd/system/oracle-audit-sniffer.service << 'EOF'
[Unit]
Description=Oracle TNS Audit Packet Sniffer
After=network.target

[Service]
ExecStart=/usr/bin/python3 /opt/audit/packet_sniffer.py \
    --oracle-port 1521 \
    --db-name ORCL \
    --db-schema FINDB
WorkingDirectory=/opt/audit
Restart=always
RestartSec=5
User=root

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable oracle-audit-sniffer
systemctl start  oracle-audit-sniffer
systemctl status oracle-audit-sniffer
```

**Windows — 작업 스케줄러**

```powershell
$action  = New-ScheduledTaskAction `
    -Execute "python" `
    -Argument "C:\audit\packet_sniffer.py --oracle-port 1521 --bind-ip 0.0.0.0 --db-name ORCL" `
    -WorkingDirectory "C:\audit"
$trigger = New-ScheduledTaskTrigger -AtStartup
$settings = New-ScheduledTaskSettingsSet -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1)
Register-ScheduledTask `
    -TaskName "OracleAuditSniffer" `
    -Action $action `
    -Trigger $trigger `
    -Settings $settings `
    -RunLevel Highest `
    -Force
```

## 로그 조회

### 웹 조회 (log_viewer_web.py)

```bash
python3 log_viewer_web.py                          # http://localhost:8888
python3 log_viewer_web.py --host 0.0.0.0 --port 9000  # 원격 접속 허용
```

브라우저에서 `http://서버IP:8888` 접속.

| 화면 | URL | 기능 |
|------|-----|------|
| 검색 | `/` 또는 `/search` | 기간·업무유형·사용자·개인정보 여부 필터 |
| 상세 | `/detail?id=...` | 6하원칙 전체 + SQL + 결과 데이터 |
| 무결성 검증 | `/verify` | SHA-256 해시 일괄 검증 |
| CSV 내보내기 | `/export` | BOM 포함 UTF-8 CSV 다운로드 |

개인정보 마스킹/원문 토글은 헤더 체크박스로 즉시 전환된다 (서버 재요청 없음).

### CLI 조회 (log_viewer.py)

```bash
python3 log_viewer.py                             # 대화형 메뉴
python3 log_viewer.py --date 20260426             # 날짜 지정
python3 log_viewer.py --op 조회                   # 업무유형 필터
python3 log_viewer.py --user U001                 # 사용자 필터
python3 log_viewer.py --pi                        # 개인정보 포함 쿼리만
python3 log_viewer.py --detail                    # 상세 출력
python3 log_viewer.py --op 조회 --pi --detail     # 복합 필터
python3 log_viewer.py --verify                    # 무결성 검증
python3 log_viewer.py --export out.csv            # CSV 내보내기
```

    "reference_no": ""

## 운영 체크리스트

- [ ] Python 3.10 이상 설치 확인 (`python3 --version`) 또는 PyInstaller 빌드
- [ ] root(Linux) 또는 관리자(Windows) 권한 확인
- [ ] Oracle 서버에 직접 설치, 또는 스위치 SPAN 포트 연결 서버에 설치
- [ ] `config.py`의 `LOG_DIR`, `DB_SERVER`, `DB_NAME`, `DB_SCHEMA` 실제 값으로 수정
- [ ] `logs/` 디렉토리 쓰기 권한 확인
- [ ] 수동 실행으로 SQL 캡처 테스트 후 `logs/*.jsonl` 생성 확인
- [ ] Oracle ASO(Advanced Security) 암호화 사용 여부 확인 (암호화 시 SQL 추출 불가)
- [ ] systemd(Linux) 또는 작업 스케줄러(Windows)로 서비스 등록
- [ ] `logs/*.jsonl` 주기적 백업 (일별 최대 200 MB)
- [ ] `python3 log_viewer.py --verify`로 무결성 주기 검증
- [ ] 웹 조회 서버(8888) 접근을 조회 담당자 IP로 방화벽 제한

## 취약점 분석 및 보안적 안전성

### 1. 로그 무결성

**구현**: 각 로그 엔트리에 `integrity_hash = sha256(log_id + start_time + sql + status)` 를 기록한다.

| 평가 항목 | 내용 |
|-----------|------|
| 변조 탐지 | 로그 파일을 직접 편집하면 해시 불일치로 즉시 탐지됨 |
| 검증 명령 | `python3 log_viewer.py --verify` 또는 웹 `/verify` |
| 취약점 | 해시가 로그 파일 **내부**에 저장되므로 해시와 내용을 동시에 조작하면 탐지 불가 |
| 권고 | 운영 환경에서는 별도 WORM 저장소나 외부 해시 레지스트리에 해시값을 보관한다 |

### 2. 개인정보 보호

**구현**: 5개 유형(주민등록번호·카드번호·계좌번호·전화번호·이메일) 패턴 자동 탐지. 웹 뷰어는 마스킹/원문 두 형태를 HTML에 포함하고 JS로 토글한다.

| 평가 항목 | 내용 |
|-----------|------|
| 마스킹 위치 | **뷰어 표시 단계**에서만 마스킹. 로그 파일에는 원문이 그대로 저장됨 |
| 취약점 | 로그 파일 직접 접근 시 개인정보 원문 노출 가능 |
| 권고 | `logs/` 디렉토리 권한을 감사 서비스 계정만 쓰기/읽기 가능하도록 제한 (`chmod 700 logs/`) |
| 개인정보보호법 | result_data에 개인정보가 포함되는 경우 로그 자체가 개인정보 파일에 해당. 접근권한 관리·보관기간 정책 필요 |

### 3. 웹 조회 서버 접근 통제

**구현**: Python 내장 `http.server` 기반. 인증 기능 없음.

| 평가 항목 | 내용 |
|-----------|------|
| 인증 없음 | URL을 알면 누구나 조회·CSV 다운로드 가능 |
| 평문 전송 | HTTPS 미지원. HTTP 평문으로 개인정보 포함 응답 전송 |
| XSS | 결과 데이터를 HTML에 삽입 시 이스케이프 처리됨. 위험도 낮음 |
| CSRF | 조회 전용(GET만 사용). 상태 변경 없음. 위험도 낮음 |
| 권고 1 | 반드시 **내부망 전용**으로 운영. 인터넷에 노출 금지 |
| 권고 2 | 방화벽에서 8888 포트를 조회 담당자 IP 대역으로만 허용 |
| 권고 3 | 보안 강화 시 nginx/Apache를 앞에 두고 Basic Auth + HTTPS 적용 |

### 4. 원시 소켓 권한 위험

**구현**: `AF_PACKET`(Linux) / `SIO_RCVALL`(Windows) 소켓으로 모든 네트워크 패킷을 수신한다.

| 평가 항목 | 내용 |
|-----------|------|
| 요구 권한 | Linux: root, Windows: 관리자 |
| 위험 | root로 실행되는 프로세스가 악용되면 시스템 전체 위협 |
| 코드 안전성 | 네트워크 입력만 처리. 파일 쓰기(`logs/`)만 수행. 외부 명령 실행 없음 |
| 권고 | Linux에서 `CAP_NET_RAW` capability만 부여하면 root 없이도 실행 가능 |

```bash
# root 없이 실행하는 방법 (Linux)
sudo setcap cap_net_raw+ep /usr/bin/python3
python3 packet_sniffer.py --oracle-port 1521
```

### 5. 로그 파일 보안

| 항목 | 현재 구현 | 권고 |
|------|-----------|------|
| 저장 형식 | UTF-8 평문 JSONL | 별도 파티션 마운트 후 암호화 저장소 적용 |
| 파일 권한 | config.py의 `LOG_DIR` 경로 기본값 | `chmod 640`, 소유자: 감사 계정 |
| 로그 삭제 방지 | 없음 | append-only 파일시스템(chattr +a) 적용 권고 |
| 최대 크기 | 200 MB/파일, 자동 분할 | 파티션 모니터링 필요 |

```bash
# append-only 설정 (Linux, root)
chattr +a /opt/audit/logs/
```

### 6. Oracle ASO 암호화 환경

Oracle Advanced Security Option(ASO)으로 TNS 트래픽이 암호화된 경우 **SQL 추출 불가**하다. 암호화된 바이트만 캡처되므로 로그에 SQL이 기록되지 않는다.

| 확인 방법 | 명령 |
|-----------|------|
| 암호화 여부 확인 | `SELECT network_service_banner FROM v$session_connect_info;` |
| 암호화 해제 가능 여부 | DBA 협의 필요 (보안 정책과 상충될 수 있음) |

### 7. TCP 재조합 한계

packet_sniffer.py는 TCP 스트림 재조합을 TNS 헤더 길이 필드 기준으로 수행한다.

| 한계 | 설명 |
|------|------|
| 대용량 SQL 누락 | 패킷 재정렬(out-of-order) 발생 시 일부 SQL 유실 가능 |
| 바인드 변수 | TNS 스니퍼는 바인드 변수 실제 값을 완전히 추출하기 어려움 |
| 감사 완전성 | 100% 캡처를 보장하지 않음. 보조 감사 수단(DB 자체 감사 로그)과 병행 권고 |

### 8. 금융 규제 준수 체크

| 규정 | 관련 항목 | 충족 여부 |
|------|-----------|-----------|
| 전자금융감독규정 §32 | 접근기록 6개월 이상 보관 | ✅ 로그 파일 보관 (기간은 운영 정책으로 설정) |
| 전자금융감독규정 §32 | 접근기록 위·변조 방지 | ⚠ SHA-256 해시 제공. WORM 저장소 권고 |
| 개인정보보호법 §29 | 개인정보 접근통제 | ⚠ logs/ 파일 권한 + 웹 서버 IP 제한 필수 |
| 개인정보보호법 §29 | 개인정보 전송 암호화 | ⚠ 웹 뷰어 HTTP 평문 → nginx+HTTPS 추가 권고 |
| 금융위 ISMS-P | 비인가 접근 탐지 | ✅ 모든 쿼리 6하원칙 기록 |

## 제약 사항

| 항목 | 내용 |
|------|------|
| 지원 DB | Oracle TNS 프로토콜 전용. PostgreSQL/MySQL/MSSQL 등 불가 |
| Oracle ASO 암호화 | TNS 암호화 시 SQL 추출 불가 |
| result_data | NUMBER/DATE 컬럼은 바이너리 인코딩이므로 제외됨. VARCHAR2/CHAR만 추출 |
| 바인드 변수 | 실제 값 추출 제한 (SQL 구조만 캡처됨) |
| TCP 재조합 | 대용량 SQL이 여러 패킷으로 분할되면 일부 누락 가능 |
| Linux 권한 | root 또는 `CAP_NET_RAW` capability 필요 |
| Windows 권한 | 관리자 권한 필요. 일부 구성에서 아웃바운드 패킷 캡처 제한 있음 |
| 설치 위치 | Oracle 서버 직접 설치, 또는 스위치 SPAN 포트 서버. 일반 L2 세그먼트의 다른 서버에서는 유니캐스트 차단으로 불가 |
