# DB 쿼리 감사 로그 시스템 — 사용법

## 시스템 개요

DB 쿼리를 OS 네트워크 레벨에서 수동 감청해 **6하원칙(누가/언제/어디서/무엇을/어떻게/왜)** 에 따라 자동으로 로그를 기록한다. 애플리케이션과 DB 서버 설정을 전혀 변경하지 않아도 된다.

- Python 표준 라이브러리만 사용 (외부 패키지 없음)
- 폐쇄망 반입 가능 (Python embeddable 포함 deploy 패키지 제공)
- 일별 JSONL 로그 + SHA-256 무결성 해시
- 웹(포트 8888) / CLI 조회 모두 지원

| 지원 DB | 스니퍼 | 기본 포트 |
|---------|--------|-----------|
| Oracle | `packet_sniffer.py` | 1521 |
| PostgreSQL | `pg_sniffer.py` | 5432 |

### 아키텍처

```
[DB 클라이언트 앱] ──TCP──▶ [DB 서버 (Oracle / PostgreSQL)]
                                        │
                          OS 네트워크 스택이 패킷 복사
                                        │
                   ┌────────────────────┴──────────────────────┐
                   │ packet_sniffer.py                         │ pg_sniffer.py
                   │ (Oracle TNS)                              │ (PostgreSQL Wire Protocol)
                   └────────────────────┬──────────────────────┘
                                        │
                               logs/audit_query_YYYYMMDD.jsonl
                                        │
                     ┌──────────────────┤
                     ▼                  ▼
            log_viewer_web.py     log_viewer.py
            (http://호스트:8888)   (CLI)
```

## Python 패키지 준비 전 환경 확인

deploy 폴더를 반입하기 전, 대상 서버의 환경 정보를 먼저 파악해야 한다.  
환경에 따라 Python 패키지 종류(embeddable ZIP / .deb / .rpm)와 실행 방식이 달라진다.

---

### Windows 환경 체크리스트

> Windows PC에 Python이 없는 경우 `deploy\python\` 폴더에 포함된 **Python 3.13 embeddable 패키지**를 그대로 사용한다.  
> 이미 Python이 설치되어 있으면 embeddable 없이도 실행 가능하다.

| # | 확인 항목 | 확인 명령 / 방법 | 비고 |
|---|-----------|------------------|------|
| 1 | **OS 버전** | `winver` 실행 | Windows 10 이상 권장 |
| 2 | **CPU 아키텍처** | `echo %PROCESSOR_ARCHITECTURE%` | `AMD64` (64비트) 인지 확인 |
| 3 | **Python 설치 여부** | `python --version` | 설치됐으면 embeddable 불필요 |
| 4 | **관리자 권한 여부** | 우클릭 → "관리자로 실행" 가능 여부 | 패킷 스니퍼 실행 필수 조건 |
| 5 | **NIC IP 주소** | `ipconfig` | `--bind-ip` 파라미터에 사용 |
| 6 | **DB 종류 + 포트** | DBA에게 문의 | Oracle 기본 1521, PostgreSQL 기본 5432 |
| 7 | **방화벽 정책** | 8888 포트 오픈 여부 확인 | 웹 뷰어 접속용 |

```
Windows 체크리스트 요약
  □ OS 버전       예) Windows Server 2019 / Windows 10 22H2
  □ CPU 아키텍처  예) AMD64 (64비트)
  □ Python 설치   예) 미설치 → embeddable 사용 / 3.10 설치됨 → 시스템 Python 사용
  □ 관리자 권한   예) 가능 / CMD 우클릭 필요
  □ NIC IP        예) 192.168.1.100
  □ DB 종류+포트  예) Oracle 1521 / PostgreSQL 5432
  □ 방화벽 8888   예) 오픈 / 별도 요청 필요
```

### Linux 환경 체크리스트

> Linux 서버에 Python이 없는 경우 배포판에 맞는 패키지(.deb/.rpm)를 외부망에서 다운받아 반입해야 한다.  
> 이미 Python 3.8 이상이 설치된 서버라면 별도 패키지 없이 바로 실행 가능하다.

| # | 확인 항목 | 확인 명령 | 예시 결과 |
|---|-----------|-----------|-----------|
| 1 | **OS 배포판 + 버전** | `cat /etc/os-release` | Ubuntu 22.04 / RHEL 8.6 |
| 2 | **CPU 아키텍처** | `uname -m` | `x86_64` / `aarch64` |
| 3 | **Python 설치 여부 + 버전** | `python3 --version` | 3.10.12 / 미설치 |
| 4 | **패키지 관리자** | `which apt` 또는 `which yum` | apt(Ubuntu/Debian) / yum·dnf(RHEL 계열) |
| 5 | **NIC 이름** | `ip link show` 또는 `ifconfig` | `eth0` / `ens33` / `bond0` |
| 6 | **root / sudo 권한** | `sudo -l` | 패킷 캡처에 반드시 필요 |
| 7 | **SELinux / AppArmor 활성** | `getenforce` / `aa-status` | Enforcing이면 raw socket 차단 가능 |
| 8 | **systemd 사용 가능** | `systemctl --version` | 부팅 시 자동 실행 서비스 등록용 |
| 9 | **DB 종류 + 포트** | DBA에게 문의 | Oracle 1521 / PostgreSQL 5432 |
| 10 | **방화벽 정책** | `firewall-cmd --list-all` / `ufw status` | 8888 포트 오픈 여부 |

```
Linux 체크리스트 요약
  □ OS 배포판+버전  예) Ubuntu 22.04 LTS / RHEL 8.6 / Rocky Linux 9
  □ CPU 아키텍처   예) x86_64 (일반 서버) / aarch64 (ARM 서버)
  □ Python 버전    예) 3.10.12 설치됨 / 미설치
  □ 패키지 관리자  예) apt / yum / dnf / zypper
  □ NIC 이름       예) eth0 / ens33 / bond0
  □ root/sudo 권한 예) root 사용 가능 / sudo 가능 / 권한 없음
  □ SELinux 활성   예) Disabled / Permissive / Enforcing
  □ systemd 여부   예) 사용 가능 / SysVinit 사용
  □ DB 종류+포트   예) Oracle 1521 / PostgreSQL 5432
  □ 방화벽 8888    예) 오픈 / iptables 추가 필요
```

### 배포판별 Python 패키지 준비 방법 (외부망 PC에서 사전 준비)

#### Ubuntu / Debian 계열

```bash
# 외부망 PC에서 실행 (배포판과 동일 버전 환경 필요)
apt-get download python3 python3-minimal libpython3-stdlib
# → 생성된 .deb 파일을 USB에 담아 내부망으로 반입

# 내부망 서버에서 설치
sudo dpkg -i *.deb
```

#### RHEL / CentOS / Rocky Linux 계열

```bash
# 외부망 PC에서 실행
yumdownloader --resolve python3
# → 생성된 .rpm 파일을 USB에 담아 내부망으로 반입

# 내부망 서버에서 설치
sudo rpm -ivh *.rpm
```

#### Python이 이미 설치된 경우

```bash
# 버전 확인 후 3.8 이상이면 바로 사용 가능
python3 --version

# 런처 스크립트가 시스템 Python을 자동으로 감지함
bash run_viewer_web.sh
```

## Oracle TNS 패킷 스니퍼 (packet_sniffer.py)

### 파라미터

```bash
# Linux (root 필수)
sudo python3 packet_sniffer.py \
    --oracle-port 1521 \      # 감청할 Oracle TNS 리스너 포트
    --db-server 192.168.1.10 \ # 로그에 기록할 Oracle 서버 IP (라벨)
    --db-name ORCL \           # 로그에 기록할 서비스명
    --db-schema FINDB          # 로그에 기록할 스키마명

# Windows (관리자 CMD 필수)
python packet_sniffer.py --oracle-port 1521 --bind-ip 192.168.1.10 --db-name ORCL
```

| 파라미터 | 설명 | 기본값 |
|----------|------|--------|
| `--oracle-port` | 감청할 TNS 리스너 포트 | 1521 |
| `--db-server` | 로그용 Oracle 서버 명칭 | config.py 값 |
| `--db-name` | 로그용 서비스명/SID | config.py 값 |
| `--db-schema` | 로그용 스키마명 | config.py 값 |
| `--bind-ip` | (Windows 전용) 바인딩 NIC IP | 자동 감지 |

#### db-schema 확인 방법

```sql
-- Oracle: 테이블 소유자(= 스키마) 목록
SELECT DISTINCT owner FROM dba_objects WHERE object_type = 'TABLE' ORDER BY 1;
-- 또는 현재 세션의 스키마
SELECT SYS_CONTEXT('USERENV','CURRENT_SCHEMA') FROM dual;
```

### 설치 위치 선택

| 설치 위치 | 가능 여부 | 조건 |
|-----------|-----------|------|
| Oracle 서버 직접 | ✅ 최선 | root/관리자 권한만 있으면 됨 |
| 스위치 SPAN 포트 연결 서버 | ✅ 가능 | 스위치 포트 미러링 설정 필요 |
| 동일 L2 세그먼트 다른 서버 | ❌ 불가 | 스위치가 유니캐스트 차단 |

### 서비스 등록 — systemd

```bash
cat > /etc/systemd/system/oracle-audit-sniffer.service << 'EOF'
[Unit]
Description=Oracle TNS Audit Packet Sniffer
After=network.target

[Service]
ExecStart=/usr/bin/python3 /opt/audit/packet_sniffer.py \
    --oracle-port 1521 --db-name ORCL --db-schema FINDB
WorkingDirectory=/opt/audit
Restart=always
RestartSec=5
User=root

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload && systemctl enable --now oracle-audit-sniffer
```

## PostgreSQL 패킷 스니퍼 (pg_sniffer.py)

Oracle과 달리 `oracle_proxy.py`에 의존하지 않는다. PostgreSQL Wire Protocol v3 파서를 내부에 자체 구현한다.

### 파라미터

```bash
# Linux (root 필수)
sudo python3 pg_sniffer.py \
    --pg-port 5432 \          # 감청할 PostgreSQL 포트
    --db-server 192.168.1.20 \ # 로그용 PostgreSQL 서버 IP (라벨)
    --db-name mydb \           # 로그용 DB명
    --db-schema public         # 로그용 스키마명

# Windows (관리자 CMD 필수)
python pg_sniffer.py --pg-port 5432 --bind-ip 192.168.1.20 --db-name mydb
```

| 파라미터 | 설명 | 기본값 |
|----------|------|--------|
| `--pg-port` | 감청할 PostgreSQL 포트 | 5432 |
| `--db-server` | 로그용 서버 명칭 | config.py 값 |
| `--db-name` | 로그용 DB명 | config.py 값 |
| `--db-schema` | 로그용 스키마명 | config.py 값 |
| `--bind-ip` | (Windows 전용) 바인딩 NIC IP | 자동 감지 |

#### db-schema 확인 방법

```sql
-- PostgreSQL: 스키마 목록
SELECT schema_name FROM information_schema.schemata ORDER BY schema_name;
-- 테이블이 있는 스키마
SELECT DISTINCT table_schema FROM information_schema.tables WHERE table_type='BASE TABLE';
```

### 캡처 방식

| 쿼리 유형 | 감지 방법 |
|-----------|-----------|
| Simple Query | 클라이언트 `Q` 메시지에서 SQL 직접 추출 |
| Extended Query (prepared stmt) | `P`(Parse) 메시지에서 SQL 저장 → `E`(Execute)에서 실행 |
| SELECT 결과 | `D`(DataRow) 메시지에서 컬럼 값 추출 |
| DML 결과 | `C`(CommandComplete) 태그에서 영향 행수 추출 |

### SSL 암호화 제약

`sslmode=require` 또는 PostgreSQL `ssl=on` 환경에서는 SQL 추출 불가. 스니퍼가 SSL 핸드셰이크를 감지하면 경고 로그를 남기고 해당 세션을 건너뛴다.

```sql
-- PostgreSQL: SSL 설정 확인
SHOW ssl;                    -- on / off
SELECT ssl FROM pg_stat_ssl WHERE pid = pg_backend_pid();
```

비암호화 연결 강제 설정(내부망 전용 환경):

```
# postgresql.conf
ssl = off
```

### 서비스 등록 — systemd

```bash
cat > /etc/systemd/system/pg-audit-sniffer.service << 'EOF'
[Unit]
Description=PostgreSQL Audit Packet Sniffer
After=network.target

[Service]
ExecStart=/usr/bin/python3 /opt/audit/pg_sniffer.py \
    --pg-port 5432 --db-name mydb --db-schema public
WorkingDirectory=/opt/audit
Restart=always
RestartSec=5
User=root

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload && systemctl enable --now pg-audit-sniffer
```

## 로그 조회

### 웹 조회 (log_viewer_web.py)

```bash
python3 log_viewer_web.py                           # http://localhost:8888
python3 log_viewer_web.py --host 0.0.0.0 --port 9000  # 원격 접속
```

| 화면 | URL | 기능 |
|------|-----|------|
| 검색 | `/` | 기간·업무유형·사용자·개인정보 여부 필터 |
| 상세 | `/detail?id=...` | 6하원칙 전체 + SQL + 결과 데이터 |
| 무결성 검증 | `/verify` | SHA-256 해시 일괄 검증 |
| CSV 내보내기 | `/export` | BOM 포함 UTF-8 CSV |

### CLI 조회 (log_viewer.py)

```bash
python3 log_viewer.py                              # 대화형 메뉴
python3 log_viewer.py --date 20260426              # 날짜 지정
python3 log_viewer.py --op 조회                    # 업무유형 필터
python3 log_viewer.py --pi --detail                # 개인정보 포함 + 상세
python3 log_viewer.py --verify                     # 무결성 검증
python3 log_viewer.py --export out.csv             # CSV 내보내기
```

    "result_data": [...]       // VARCHAR2/CHAR(Oracle) 또는 text 컬럼 값 목록
  },
  "integrity_hash": "sha256(log_id+start_time+sql+status)"

## 취약점 분석 및 보안적 안전성

### 1. 로그 무결성

**구현**: 각 로그 엔트리에 `integrity_hash = sha256(log_id + start_time + sql + status)` 기록.

| 평가 항목 | 내용 |
|-----------|------|
| 변조 탐지 | 로그 파일 직접 편집 시 해시 불일치로 즉시 탐지 |
| 검증 명령 | `python3 log_viewer.py --verify` 또는 웹 `/verify` |
| 취약점 | 해시가 로그 파일 **내부**에 저장 → 해시+내용 동시 조작 시 탐지 불가 |
| 권고 | 별도 WORM 저장소나 외부 해시 레지스트리에 해시값 보관 |

### 2. 개인정보 보호

**구현**: 5개 유형(주민등록번호·카드번호·계좌번호·전화번호·이메일) 자동 탐지. 웹 뷰어에서 마스킹/원문 토글.

| 평가 항목 | 내용 |
|-----------|------|
| 마스킹 위치 | 뷰어 표시 단계에서만 마스킹. **로그 파일에는 원문 저장** |
| 취약점 | 로그 파일 직접 접근 시 개인정보 원문 노출 |
| 권고 | `chmod 700 logs/` + 감사 계정만 접근 허용 |
| 개인정보보호법 | result_data에 개인정보 포함 시 접근권한 관리·보관기간 정책 필요 |

### 3. 웹 조회 서버 접근 통제

**구현**: Python 내장 `http.server` 기반. **인증 기능 없음.**

| 평가 항목 | 내용 |
|-----------|------|
| 인증 없음 | URL 알면 누구나 조회·CSV 다운로드 가능 |
| 평문 전송 | HTTPS 미지원. HTTP 평문으로 개인정보 전송 |
| XSS | HTML 이스케이프 처리됨. 위험도 낮음 |
| CSRF | 조회 전용(GET만). 상태 변경 없음. 위험도 낮음 |
| 권고 1 | **반드시 내부망 전용**. 인터넷 노출 절대 금지 |
| 권고 2 | 방화벽에서 8888 포트를 조회 담당자 IP 대역만 허용 |
| 권고 3 | nginx/Apache + Basic Auth + HTTPS 앞단 구성 권고 |

### 4. 원시 소켓 권한 위험

**구현**: `AF_PACKET`(Linux) / `SIO_RCVALL`(Windows)으로 모든 네트워크 패킷 수신.

| 평가 항목 | 내용 |
|-----------|------|
| 요구 권한 | Linux: root, Windows: 관리자 |
| 코드 안전성 | 네트워크 입력만 처리. 외부 명령 실행 없음. `logs/` 쓰기만 수행 |
| 권고 | Linux에서 `CAP_NET_RAW` capability만 부여 → root 없이 실행 가능 |

```bash
# root 없이 실행 (Linux)
sudo setcap cap_net_raw+ep /usr/bin/python3
python3 packet_sniffer.py --oracle-port 1521
```

### 5. 로그 파일 보안

| 항목 | 현재 구현 | 권고 |
|------|-----------|------|
| 저장 형식 | UTF-8 평문 JSONL | 별도 파티션 + 암호화 저장소 |
| 파일 권한 | `config.py`의 LOG_DIR 경로 | `chmod 640`, 소유자: 감사 계정 |
| 로그 삭제 방지 | 없음 | `chattr +a logs/` (Linux append-only) 권고 |
| 최대 크기 | 200 MB/파일 자동 분할 | 파티션 용량 모니터링 필요 |

```bash
# append-only 설정 (Linux)
sudo chattr +a /opt/audit/logs/
```

### 6. SSL/암호화 환경 제약

| DB | 암호화 확인 | 영향 |
|----|------------|------|
| Oracle | `SELECT network_service_banner FROM v$session_connect_info` | ASO 암호화 시 SQL 추출 불가 |
| PostgreSQL | `SHOW ssl;` | ssl=on 시 SSL 세션 SQL 추출 불가 |

### 7. TCP 재조합 한계

| 한계 | 설명 |
|------|------|
| 대용량 SQL 누락 | 패킷 재정렬(out-of-order) 발생 시 일부 유실 가능 |
| 바인드 변수 값 | TNS/PG 스니퍼 모두 실제 바인드 변수 값 추출 제한 |
| 감사 완전성 | 100% 캡처 보장 않음. DB 자체 감사 로그와 병행 권고 |

### 8. 금융 규제 준수 체크

| 규정 | 관련 항목 | 충족 여부 |
|------|-----------|-----------|
| 전자금융감독규정 §32 | 접근기록 6개월 이상 보관 | ✅ JSONL 파일 보관 (기간은 운영 정책) |
| 전자금융감독규정 §32 | 접근기록 위·변조 방지 | ⚠ SHA-256 해시 제공. WORM 저장소 추가 권고 |
| 개인정보보호법 §29 | 개인정보 접근통제 | ⚠ logs/ 권한 + 웹 서버 IP 제한 필수 |
| 개인정보보호법 §29 | 개인정보 전송 암호화 | ⚠ 웹 뷰어 HTTP → nginx+HTTPS 추가 권고 |
| 금융위 ISMS-P | 비인가 접근 탐지 | ✅ 모든 쿼리 6하원칙 기록 |

## 제약 사항

| 항목 | 내용 |
|------|------|
| Oracle 암호화 | ASO(Advanced Security) 암호화 시 SQL 추출 불가 |
| PostgreSQL SSL | `ssl=on` 클라이언트 세션 SQL 추출 불가 |
| result_data (Oracle) | NUMBER/DATE 컬럼 제외. VARCHAR2/CHAR만 추출 |
| result_data (PG) | text/varchar 계열 추출. bytea/jsonb 등 바이너리 제외 |
| 바인드 변수 | 실제 바인드 변수 값 추출 제한 (SQL 구조만 기록) |
| TCP 재조합 | 대용량 SQL이 여러 패킷으로 분할 시 일부 누락 가능 |
| 설치 위치 | Oracle/PG 서버 직접 설치, 또는 스위치 SPAN 포트 서버 |
| Linux 권한 | root 또는 `CAP_NET_RAW` capability 필요 |
| Windows 권한 | 관리자 권한 필요 |
